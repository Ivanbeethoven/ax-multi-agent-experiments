# 技术与消融实验

RQ 按任务提出，消融按技术拆开。系统比较回答任务表现；同一实现的一项开关比较解释性能变化。具体配对由 [comparisons.json](../configs/comparisons.json) 指定，输入、种子、缓存预算、持久完成条件和主机位置保持相同。

| 技术 | 直接实验 | 单独改变什么 | 首要指标 | 任务指标 |
|---|---|---|---|---|
| 共享父名字空间、私有目录记录 | C2 `namespace-materialized`；C4 `fork-materialized-metadata` | 派生时共享目录记录 / 复制目录记录，文件数据仍共享 | 创建的记录与字节、查询次数、准备时间 | 工作区可用时间、trace 完成时间 |
| 文件范围增量 | C4 `full-file-update` | 同一文件覆盖写使用范围记录 / 完整文件复制 | 应用写入、上传、物理写入字节 | 私有修改到远端可读的时间 |
| Packed 联合索引页 | C3 `metadata-representation`、`kv-no-metadata-cache` | 联合页 / KV 元数据查询，数据对象与访问序列相同 | 元数据请求、下载字节、解析 CPU | 首批数据时间、每遍读取时间 |
| 每对象编码块 B | C1 `layout-fuse`、`block-random`、`block-sequential` | 相同文件系统负载采用 64/256/1024/4096 KiB 的 B | 编码 CPU、PUT 字节、磁盘读写、实际 B | 吞吐、IOPS、持久完成时间 |
| 同机共享只读缓存 | C2/C3 `shared-host-cache`；C4 同名条件 | 每挂载独立 / 同主机共享 | 缓存副本数、重复下载、缓存总量 | 并发任务时间、首次读与重复读 |
| 工作区行缓存、整包缓存、解码保留 | 各 C 中对应缓存条件 | 仅关闭指定缓存 | 查询、下载、解码次数与 CPU | 本 C 的任务时间 |
| 差异枚举与对象引用合并 | C4 merge 四组组合 | 分别关闭差异枚举、对象引用复用 | 扫描记录、元数据请求、GET/PUT 字节 | 合并和远端可读时间 |

等待时长、并发规模、应用请求大小、写入策略属于参数影响实验，结果与技术消融分开呈现。

## Packed 的四组比较

固定 10 万个 4 KiB 只读文件、32 个读者、三遍读取。

| 组 | 元数据表示 | 元数据缓存 | 条件 |
|---|---|---|---|
| A | Packed 联合页 | 128 MiB | `C3-load-02` 的 BrewFS Packed |
| B | KV | 128 MiB | `C3-metadata-representation-01` |
| C | Packed 联合页 | 0 | `C3-metadata-cache-01` |
| D | KV | 0 | `C3-kv-no-metadata-cache-01` |

A/B 与 C/D 比较表示；A/C 与 B/D 比较缓存。四组引用相同的数据对象、相同文件属性与相同读取顺序。整包和数据缓存设置固定；关闭元数据缓存所释放的内存不转给其它缓存。KV 适配也使用 128 MiB 的显式元数据缓存预算。

## fork 后合并的四组比较

固定父目录 10 万文件，子工作区执行 100 项修改，父工作区保持共同版本。所有组使用同一提交和冲突检查实现。

| 组 | 查找修改 | 应用数据修改 | 条件 |
|---|---|---|---|
| A | 增量记录 | 复用对象引用 | `C4-merge-size-02` 的 BrewFS |
| B | 完整目录遍历 | 复用对象引用 | `C4-merge-tree-scan-01` |
| C | 增量记录 | 读取并写入修改文件 | `C4-merge-materialize-01` |
| D | 完整目录遍历 | 读取并写入修改文件 | `C4-merge-tree-materialize-01` |

A/B、C/D 解释元数据枚举成本；A/C、B/D 解释数据复用成本。分别报告 diff、冲突检查、apply、持久完成时间，以及扫描记录数和对象字节。两因素同时关闭的 D 用于判断二者是否相互影响。

当前 Native merge 已提供增量扫描、引用复用及原子提交，AX 调用入口已接入。B/C/D 的独立策略开关需要在同一实现中补齐，详细接口状态见 [C4 adapters](../experiments/c4-fork/adapters.json)。Native 当前只返回总结果和记录数，内部分段时间在增加计时后记录。`merge-posix-brewfs` 同时改变发现与应用阶段，作为整体方法比较，不计入上述单项消融。

C4 还改变 target 已有修改量并连续归并 4/16/64 个 child，测量两侧私有记录及 target 累积增长的实际成本。`scanned_records` 与 POSIX 的目录项枚举数分列，元数据总访问另用 Redis 指标统计。

## 共用执行方法

每个配对重复三次，使用同一整数种子生成输入与偏移；比较组交替执行。每次还原相同初态，冷态与热态单独记录。关闭缓存时保留原总资源上限，其余缓存容量不变；共享缓存时总容量等于参与挂载的原有只读缓存总量，写入缓存仍独立。共享与独立两组的每主机下载/上传/HEAD 总并发相同，缓存所有者使用原有客户端 CPU/内存预算。

输出每次原始值、配对比值和三次的范围。分位数来自同一运行的原始直方图，按任务类型分别汇总。只有三次重复时不宣称细小差异已经稳定。

待实现接口集中列在 [SETUP](SETUP.md)。每个开关都需要记录实际生效配置和对应计数变化；实现尚未提供的条件保留 `pending-feature`，其余条件继续执行。
