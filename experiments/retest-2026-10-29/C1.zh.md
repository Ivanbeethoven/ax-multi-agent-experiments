# C1：共享后端上的 Agent 文件访问

## 实验设置

主对照为 BrewFS Overlay/native lower 与 JuiceFS，两者使用共享 Redis 和同一 RustFS 服务池。BrewFS flat-v1/Overlay 作为独立内部对照。每个 Agent 拥有独立可写目录、HOME/XDG、挂载与缓存。

当前并发为1/4/8 Agent。运行环境由[SSH清单](runbook/SSH-RUN.zh.md)分配；8个容器可以分布在若干宿主。并发级别之间固定后端预算，同一配对条件固定Agent位置、配额、输入和缓存状态。

## 实验配置

| 项目 | 配置 |
|---|---|
| BrewFS | 开批核最新main并冻结SHA；workspace-native-v2、native_p1_catalog非空immutable lower、独立writable head |
| JuiceFS | v1.4.2，固定二进制SHA |
| Redis | 直接连接同一独立服务；AOF开启、appendfsync=always、noeviction；内存及服务配额按交付清单冻结 |
| RustFS | Ivanbeethoven/rustfs 的 feat/dynamic-block-size-rebased；源码、OCI revision与digest一致，核实际EC2+2布局 |
| Agent | FUSE＋回放器合计2CPU/8GiB、swap=0；缓存、预读与上传并发逐项记录 |
| 写入 | BrewFS upload_before_commit；JuiceFS客户端writeback关闭；应用完成、排空与远端确认分别计时 |
| 缓存 | 正常kernel cache；每cohort新挂载和客户端缓存；服务端以同一初态读取流程准备 |
| 数据 | 完整trace、全部xattr与真实写入载荷；输入放被测挂载之外，计时前核SHA |
| 隔离 | 本批专用volume/workspace/DB/namespace，记录实际身份；切换方法时按清单恢复初态 |
| 其他 | 客户端压缩、Pack、dynamic hint和LLM等待关闭；数据路径采用Redis，C1不部署Manager |

具体缓存数值、磁盘空间、服务限额和网络实测进入本批配置，硬件预算由实际峰值确定。应用trace中的SQLite文件仍按原样回放。

## 方法与矩阵

| 阶段 | 输入与并发 | 对照与重复 | cohort数 |
|---|---|---|---:|
| P：流程试跑 | pytest-full-02，N=1/8 | Overlay/JuiceFS各1个区组 | 4 |
| M1：弱扩展 | django、ripgrep-20261026、archive-io-20261026；N=1/4/8 | 两臂×3个区组 | 54 |
| M2：覆盖 | sklearn、sympy、pytest-full-02、pytest-20261026；N=1 | 两臂×3个区组 | 24 |
| M3：固定队列 | ripgrep 128任务＋archive-I/O 128任务；N=8，每Agent各16＋16 | 两臂×3个区组 | 6 |
| A：内部对照 | 三份扩展负载；N=1/8 | flat-v1/Overlay×3个独立区组 | 36 |

P使用pilot-8，正式使用c1-8，provider=ssh。正式主线84＋内部36个cohort；条件、配对顺序和seed在运行前冻结。一个cohort是某方法、输入与并发条件的一次完整批次。

1. 核归档、初末树与全部blobs；通过生产路径建立非空native lower，验证head写入、隔离、重新挂载和内容。
2. 准备相同初态。导入、fork/clone、构建、输入分发和校验在计时外完成。
3. 验收实际配额、容量/inode余量、网络、输入读取和解析器峰值；Django events约21.36GiB，需实测8GiB环境的RSS。
4. 固定原生指标与[观测开销资格](runbook/OBSERVABILITY.zh.md)。所有worker完成预检，协调器一次释放屏障。
5. 用Rust full-fuse-replay处理完整任务，保留全部操作和字节，不设总回放时限。固定队列复用预先分配的任务顺序。
6. 保存应用完成、drain和独立读回三个阶段，核最终内容及采样，再保全所有结果。

## 测量指标

| 层 | 记录 |
|---|---|
| 批次/任务 | 完成与失败数、任务/s、makespan、任务分位数及样本数、相对N=1慢化、活跃曲线 |
| 文件系统 | ops、读写字节、errno差异、handles、最终内容；FUSE/metadata计数与延迟 |
| 持久性 | 应用结束到排空/远端确认的间隔、dirty/pending/inflight/staging |
| 客户端/宿主 | CPU/RSS、cgroup峰值/OOM/节流、PSI、缓存、输入盘、网络、设备IO、steal |
| 后端 | Redis命令及AOF、RustFS请求和布局、资源使用、失败/重试、磁盘及网络限速 |

每个区组保留原值，报告配对比值、中位数与范围。失败、慢值、缺测一并列出。8任务的经验p99接近最大值，标注样本数。

pytest-full-02每次应有1,747,109 ops、读281,774,624 B、写194,706,661 B、handles=0。performance完成与严格内容资格分别报告；errno差异若造成实际工作量变化，该条件需先排查。Trace回放重现文件访问顺序，不重新调用模型或恢复原应用线程。
