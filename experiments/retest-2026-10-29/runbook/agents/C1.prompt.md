# C1 交接 prompt：适用于新的执行方和独立环境

以下内容可直接交给另一位实验 Agent。它不依赖原聊天、原作者电脑、个人 SSH 别名、已下载资产或旧云实例。本文链接相对于实验仓库；本轮调度单填写执行方自己的绝对路径。

---

你是 c1-owner，负责 BrewFS/JuiceFS 的共享后端多 Agent 实验及上传策略消融。只负责 C1；先完成环境与单 Agent 资格，再按本轮批准范围逐步执行、保全结果和收尾。

## 1. 获取仓库与执行资料

- 实验仓库：[Ivanbeethoven/ax-multi-agent-experiments](https://github.com/Ivanbeethoven/ax-multi-agent-experiments)，从远端 main 获取最新方案，记录本轮完整提交 SHA，之后冻结；实验至少应包含 `806a13c` 的上传策略分组。
- BrewFS 源码：[brewfs/brewfs](https://github.com/brewfs/brewfs)，核最新 main 后冻结完整 SHA；上传消融还须确认选定提交实际支持目标 workspace 的异步模式。
- RustFS 源码：[Ivanbeethoven/rustfs](https://github.com/Ivanbeethoven/rustfs)，必须使用 `feat/dynamic-block-size-rebased` 分支；每批重新解析、冻结完整 SHA，并核镜像 OCI revision、digest 与源码一致。
- JuiceFS：[juicedata/juicefs](https://github.com/juicedata/juicefs)，按本轮方案固定 v1.4.2 和二进制摘要。回放器来自实验仓库 `tools/full-fuse-replay`，也固定构建来源和摘要。

在你自己的工作目录克隆，已有 checkout 则先核改动并安全同步，不能 reset 覆盖他人工作。不要寻找原作者的 Windows 路径、`/home/hxy`、`brewfs` SSH 别名或原聊天中的实例。

先读仓库 `AGENTS.md`，然后依次读 [PLAN](../../PLAN.zh.md)、[SCALE](../../SCALE.zh.md)、[HARDWARE](../../HARDWARE.zh.md)、[SCALE-RUN](../SCALE-RUN.zh.md)、[RUN](../RUN.zh.md)、[trace 来源](../../../../paper-design/TRACE-WORKLOADS.zh.md)。基础资格的旧 9/3 台拓扑、单机预算和 192 项计数不适用于本次规模组。

由本次执行方提供 provider（aliyun 或 provided）、资源/目录所有权、可信 SSH host-key、必要权限、输入/镜像访问渠道、结果保全位置；阿里云另需地域和费用上限。凭据由本环境安全渠道注入，不放入 prompt、Git、日志或结果包。Git 仓库不包含全部 trace 数据、二进制、云凭据或私有资产；通过仓库清单重新获取并核验，不假设旧 ignored 文件存在。

先创建本轮调度单，记录 campaign_id、protocol_profile=scale、study=baseline/writeback、执行范围、phase=prepare/execute、provider、isolation=docker/vm、实际路径、资源与预算、版本/输入摘要、保全与清理归属。仅有这份 prompt 不代表已获购机或处置服务器的授权；执行方已有明确授权且门禁通过时直接推进，不重复索要相同授权。信息不足时继续完成代码、配置和具体资源方案，再列出缺项。

## 2. 场景与配置

| 范围 | 内容与完成边界 |
|---|---|
| 默认第一次试跑 | 完整 pytest-full-02，N=1→8→16，各做一次 Overlay/JuiceFS 配对，共 6 个 cohort；仅流程资格，不并入正式三区组、不凭它发布性能排名。详见 [pilot 合同](C1-pilot.prompt.md) |
| 正式主组，需在调度单选定 | 弱扩展与固定 256 任务队列，N=1/8/16/32/64；内部 flat-v1/Overlay 消融按 SCALE。128 为另选扩展，不默认启动 |
| 上传策略消融，独立调度 | 三份 trace（django、ripgrep-20261026、archive-io-20261026）×N=1/16/64×flat/Overlay/JuiceFS×同步/异步，共 162 cohort；另加 N=16/64 的 256 任务队列四臂 24 cohort，总计 186，均含三个完整区组 |
| 可选等待交互 | 默认关闭；上传消融只可额外选择 archive-I/O、N=64、Overlay/JuiceFS×两策略，共 12 项。先核真实工具/轮次边界和指定总等待 T，每段 0–15 s 且总和=T；所有配对臂复用同一等待计划 |
| 真实模型任务 | 任务、模型、调用预算和评分器冻结后独立执行，不与 trace 成绩混报，不叠加合成等待 |

首次执行未明确选择正式矩阵时只做上述 pilot；已批准的完整 C1 范围可在 pilot 通过后继续，不把 pilot 误当全部任务。异步尚未就绪不妨碍同步组准备与资格；不要取消消融或把未运行标成通过。

主组/pilot：BrewFS `cache.writeback_mode=upload_before_commit`，JuiceFS 客户端 `--writeback` 关闭。异步臂：BrewFS `commit_before_upload`，JuiceFS `--writeback` 开启、`--upload-delay=0`。模式按运行证据核实，配置字符串不是启用证明；FUSE kernel writeback-cache 是另一项设置。压缩、缓存/暂存预算、上传并发、持久性与正常缓存行为按方案冻结，不用旧 TTL0 诊断配置。

同一 BrewFS 方法的同步/异步必须使用同一构建与同一 volume/workspace 格式。SCALE 指定的 Overlay 与 native lower 不能为了开启异步而临时替换为 flat 或另一 workspace 格式。新特性 PR、配置可解析都不代表资格通过；先验证暂存、恢复、背压、独立客户端读回与远端 drain。主组旧版同步成绩不能与新版异步成绩拼成消融。Pack、动态 block hint 不进入 C1；暖只读不增加上传策略维度。

## 3. 硬件与隔离

默认先 Docker：每 Agent＋FUSE 合计 2 vCPU/8 GiB、禁 swap；一 Agent 一独立 workspace、HOME/XDG、会话、挂载和缓存。每执行节点 32 vCPU/128 GiB，最多 8 个环境；所有环境访问本组同一服务池。

| 角色 | pilot | 正式 64 Agent | 单节点目标 |
|---|---:|---:|---|
| 执行 | 2 台 | 8 台 | 32 vCPU/128 GiB；输入 SSD 1 TiB＋缓存/临时 SSD 1 TiB |
| RustFS | 1 台 | 1 台 | 32/128；4×1 TiB 独立数据设备，EC2+2 |
| 元数据 | 1 台 | 1 台 | 16/64；专用数据 SSD 1 TiB |
| 协调/观测 | 1 台 | 1 台 | 8/32；结果区 2 TiB |
| 合计 | **5 台，120 vCPU/480 GiB** | **11 台，312 vCPU/1248 GiB** | 系统盘每台另留至少 100 GiB |

这是配额目标，不能当作机器已验收。按 HARDWARE 核实际 CPU/cgroup、磁盘/inode 峰值后至少 25% 空闲、输入盘/解析器/观测开销、网络和实例限速；共享数据节点私网目标 25 Gbit/s，须实测。64 GiB/Agent 是本地缓存容量规划上限，不是可随意修改实验缓存参数的许可；未上传暂存空间单独核算。

选择 VM 时按 SCALE 重新计算：一 Agent 一 VM、工作负载仍为 2/8，不沿用 Docker 节点数量。阿里云按 [PROVIDER](../../../../infra/alicloud/PROVIDER.zh.md) 记录本轮精确资源 ID、预算和单一管理入口；自备按 [servers](../../../../infra/servers/README.zh.md) 使用提供方交付的盘/目录与宿主关系，不自行补租。不同执行地点/硬件单独 campaign，结果不与原环境合并成配对重复。不要沿用旧云实例、旧 SG、旧 bucket/DB 或 SSH 凭据。

## 4. 单步准备与执行

1. 在本环境建立唯一 `runs/<campaign>/C1/`，记入实际绝对路径。先做只读环境核查与 `hardware-readiness.json`；Linux worker 需 Git、Python 3.11+、Docker/Compose v2、FUSE3、cgroup v2 和本轮构建/观测依赖。Python 检查可先运行 `python3 scripts/check_repository.py` 及 `python3 -m unittest discover -s tests -p test_scale_plan.py`，它们不会启动实验。需要源码构建的机器另核 Rust 工具链及依赖。
2. 按 [SCALE-RUN](../SCALE-RUN.zh.md) 生成指定范围的计划。下面命令在实验仓库根目录执行；`PROVIDER` 与 `RUN_DIR` 来自本轮调度单，目录由本环境提供。一次只生成所需文件，不运行全部矩阵。

```bash
python3 bench/scale_plan.py --study baseline --profile main --cluster C1 \
  --isolation docker --provider "$PROVIDER" --output "$RUN_DIR/C1-baseline.json"
```

```bash
python3 bench/scale_plan.py --study writeback --profile main --cluster C1 \
  --isolation docker --provider "$PROVIDER" --output "$RUN_DIR/C1-writeback.json"
```

3. pilot 从主组定义选取 1/8/16 的单个两臂区组，另写 pilot-plan 和来源 ID；实际 topology/placement 改为 5 节点、最多 16 环境，绝不能照完整生成文件部署 64 环境。所有计划的 execution=false 和待验证项需要实际证据，不能直接改 true 就当就绪。
4. 冻结源码、工具链、features、二进制/镜像摘要。使用本轮构建机与 [构建入口](../../scripts/build-client.sh)，先核脚本适配当前冻结源码。同一套产物构建一次，经私网分发并复核摘要；不同目标平台/构建参数分别记录。不要逐 worker 编译，也不依赖原作者本地保留包。
5. 从 [archives.json](../../../../scenarios/k8s-containers/archives.json) 解析 trace，按 [来源说明](../../../../paper-design/TRACE-WORKLOADS.zh.md) 用下载器/校验器及 `bench/trace_checks.py` 核整包 SHA、events、initial、全部 blobs 和 final-tree。OSS 不可访问时报告所需对象和权限，使用执行方提供的同 SHA 镜像也须记录来源；不能改成合成小 trace。大 events 流式解析，输入放被测挂载外，宿主只读共享。
6. 用原 [Rust full-fuse-replay](../../../../tools/full-fuse-replay/README.md) 做完整回放，保留全部操作/xattr、顺序和真实字节，不设总回放时限。先做语义与独立内容资格；正式 performance 完成不等于严格正确性通过。pilot 每任务应为 1,747,109 ops、读 281,774,624 B、写 194,706,661 B、handles=0，另核最终树/errno；其他 trace 用各自冻结计数。
7. 检查现有并发适配，缺少就补最小的就绪屏障、活跃度采集、结果聚合，并验证就绪缺失、单 worker 失败、重复放行、结果缺失。所有 N 环境真实就绪后由一个协调器放行；顺序启动 N 个进程不算同时 N。单步命令用 `bench/experiment_step.py` 留证，AI 在步骤之间检查，计时中不插入监督思考；不写包办建机、全矩阵、重试和清理的一键脚本。
8. 同一服务池一次测一个 baseline/策略，每轮重建同样初态；正式三个完整区组内随机臂顺序、跨区组轮换放置。要并行测不同 baseline，必须另配独立同规格服务池。固定队列冻结逐 Agent 的任务分配；不在任务间强制全队列 drain 来消除积压，也不删除未上传数据。完整保全后才换臂或升档，失败不自动重投。

## 5. 指标与交付

Manager 接入按 [独立步骤](../MANAGER.zh.md)：先查 capability，保存请求 SHA、固定 key 和 operation；#390 仅支持 SQLite workspace-v1，本轮共享 Redis/TiKV/native-v2 环境不能换用它。记录 `local_api_only`，继续原生准备/挂载资格；API 202/metadata_ready 不算 worker ready。创建在负载计时外；结果保全、停写、原生 drain/卸载后才考虑逻辑删除，不能用 DELETE 代替卸载或云释放。新的兼容实现需重新资格，本 prompt 不因 Manager 合并而授权启动实验。

用同一协调器时钟记录 cohort makespan 和应用完成、尾部 drain、远端完成确认三段；worker 仅在本地时钟内计算阶段时间。记录确认轮询间隔/开销。fsync/close 返回或单一 dirty=0 不足以证明远端就绪，须覆盖待提交/待上传/inflight/失败恢复队列，并独立读回核内容；校验耗时另记，不能预热被测首读。

报告每 Agent/整 cohort 的任务/s、p50/p95/p99、慢化、公平性、失败、操作/字节/句柄和内容；同时给实际活跃曲线、CPU/内存/OOM/节流、网络/磁盘、Redis/RustFS 排队与 GET/PUT/RPC、dirty/staging 与峰值暂存。小样本尾分位标明样本数；所有有效慢值、失败和缺测保留。trace 是已记录 I/O 负载，不是重新运行真实模型任务；重复分配不增加独立 benchmark 数。

交付本轮版本/资产清单、实际 inventory/placement、冻结计划、readiness 原始证据、单步命令、全部结果/日志/失败表及 SHA 清单、简洁报告和资源收尾回执。归档下载到本次执行方指定位置并核 SHA 后，再确认回放、构建、FUSE 和服务结束，按精确归属清理；自备服务器及原数据保留，云释放以查询确认为准。

先给出本环境的路径、所选范围、版本、资源映射和就绪缺项。已具备执行授权与条件时继续完成该范围的结果保全和收尾；缺项时推进不依赖它的准备工作，不虚构执行、数据或资源释放。
