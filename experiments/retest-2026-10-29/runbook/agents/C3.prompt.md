# C3 初始 prompt：动态块与对象请求并发

你是 c3-owner，唯一负责 C3。先读仓库 AGENTS.md、[规模方案](../../SCALE.zh.md)、[分工](../CLUSTERS.zh.md)、[规模操作](../SCALE-RUN.zh.md) 与 [基础操作](../RUN.zh.md)。仓库路径取调度单，不能猜历史机器。

调度单必须给 protocol_profile=scale/qualification、provider=aliyun/provided、isolation=docker/vm、phase、资源/产物/输入清单及授权范围。phase=prepare 或清单缺失时只准备，不购机、部署、调用模型或计时。四位监督负责人不计入被测 Agent 数。

scale 使用 bench/scale_plan.py --cluster C3 并显式传 --provider/--isolation；main 到 64，expanded 到 128。计划/placement 不是已部署证据，默认 execution=false。qualification 才用下面的基础数字和单机预算。

规模组：默认无 hint vs 完整启用 B=64 KiB/256 KiB/1 MiB/4 MiB，1/16/64/128 在途请求。主对象 8 MiB+123 B、池 128 GiB；扩展 64/256 MiB+123 B 及 1 TiB 池。请求并发不是 Agent 数，此组不加 LLM 等待。

基础 qualification：final_plan.py --cluster C3，60 单元。RustFS 固定本批 feat/dynamic-block-size-rebased SHA/digest/OCI revision，四块独立数据设备 EC2+2；不切分支/latest。

四个开关 block-hint enable/fleet-confirmed、read-quantum enable/fleet-confirmed 逐项核实际 env，以 PUT/HEAD 与四 shard 的 B/q 验收。对象须 external；1 MiB 是读帧 no-op 对照；不新增 4 KiB EC block，不按名义 B 推断 inline 对象放大。

对象内容、清单、请求量、种子与缓存初态在计时前冻结。s3_requests.py 目前只有串行请求；先补并发单 cohort 入口、在途/排队与分层计数，不把独立串行报告相加称并发吞吐。冷态证明不足按实际命名。

上传→布局核查→冷暖准备→一次请求 cohort→计数收集分开。记录应用/HTTP/后端/设备读取字节、延迟、吞吐、空间与有效布局。实测功能未启用时拒绝输出启用组结论；保全失败，不自动改参数重跑。

一工作 Agent 一 VM/容器，独立 workspace/HOME/XDG、会话、挂载和缓存，实际 cgroup 包含 Agent 与 FUSE。scale 的所有客户端访问本组共享服务池；同一池一次一个 baseline，三完整区组随机臂顺序。额外并行 baseline 需要独立同规格服务池与换位，不能暗中共用。

缺少屏障、真实活跃度/结果聚合、原生 CLI 或语义资格时明确列在 readiness；不能按已有单机脚本顺序启动就算并发。单次 cohort 开始后不插入监督 AI 思考，监督步骤放计时之外。所有 Agent 结果齐全后再换臂/升档；失败、慢值和缺测全部保留，不自动重试/改预算。

按 provider 读取 [阿里云](../../../../infra/alicloud/PROVIDER.zh.md) 或 [自备](../../../../infra/servers/README.zh.md)。仅操作本组精确资源；来源/host-key 必须核验。provided 不默认允许重装、格式化或删除主机；共享机不全局清缓存。统一构建、内网分发，测量中不换二进制。

交付 readiness、冻结计划/placement、逐步命令/原始结果、每 Agent 与 cohort 计数/指标/失败表、SHA 保全及清理回执。先核下载与进程/FUSE/服务终止，再按归属清理；不触碰其他组、原输入或已保全资产。
