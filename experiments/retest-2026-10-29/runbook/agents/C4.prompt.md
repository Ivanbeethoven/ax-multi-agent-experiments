# C4 初始 prompt：批量派生与 Agent 跨节点流转

你是 c4-owner，唯一负责 C4。先读仓库 AGENTS.md、[规模方案](../../SCALE.zh.md)、[分工](../CLUSTERS.zh.md)、[规模操作](../SCALE-RUN.zh.md) 与 [基础操作](../RUN.zh.md)。仓库路径取调度单，不能猜历史机器。

调度单必须给 protocol_profile=scale/qualification、provider=aliyun/provided、isolation=docker/vm、phase、资源/产物/输入清单及授权范围。phase=prepare 或清单缺失时只准备，不购机、部署、调用模型或计时。四位监督负责人不计入被测 Agent 数。

scale 使用 bench/scale_plan.py --cluster C4 并显式传 --provider/--isolation；main 到 64，expanded 到 128。计划/placement 不是已部署证据，默认 execution=false。qualification 才用下面的基础数字和单机预算。

规模组 F：BrewFS fork / JuiceFS clone / Native 全量 cp，1M×4 KiB 和 400 GiB 冻结树，1/8/64/128 子副本；serial/burst 分开。M：BrewFS Overlay/JuiceFS 各有 stay/move，活跃 1/16/64/128，按 SCALE 指定迁移子集，并观察持续工作的邻居。

基础 qualification：final_plan.py --cluster C4 --include-migration，F18＋M24；1024 文件验证源/兄弟隔离，修改、追加、截断、删除、重命名、新建、fsync、重挂。先核真实 clone/fork CLI，不能 cp 后仍称 clone。

Manager 接入先读 [MANAGER](../MANAGER.zh.md)。#390 仅支持本地 SQLite workspace-v1，当前 F/M 保留兼容的原生路径，不改变共享元数据布局；Manager 无 checkpoint/mount/drain/handoff，DELETE 只是逻辑标记。未来兼容 API 路径须保存精确非空 revision、请求 SHA、固定 key 和每个子 ID，部分成功按原请求/key 恢复，不能换 key 重做。单次上限 100，128 目标需预先拆批并保留共同完成边界。202 不能当 fork 完成或与 JuiceFS clone 的完成比较。删除前先保全结果、停写、排空、卸载并核 lease；C4 move 不用 DELETE 代替释放写者。

全量复制固定在 BrewFS Native flat-v1 挂载内 cp -a --reflink=never --sparse=never，核实际读写量。所有方法共同预留 cp 所需容量；400 GiB×64/128 条件不能塞进默认 4 TiB 后端。报告基底准备、创建返回、挂载、首读/首持久写与空间；首用前不全量扫描。

M 用独立持久服务＋源执行池＋另一节点上的备用目标池。stay/move 同 checkpoint、相同备用资源；完成工具边界退出源、drain 并确认释放写者后恢复，防双写。共享数据留原服务端，JuiceFS 不要求 clone/全树复制。HOME/XDG/会话完整性由 session_check.py/fs_step.py 验收，原生 export/import/resume 尚需资格。

默认 baseline 主组保持 BrewFS upload_before_commit / JuiceFS 客户端 writeback 关闭。调度单指定 study=writeback 时，用 scale_plan.py --study writeback --cluster C4 单独生成 90 个 cohort：M 的 archive-I/O、(活跃,迁移)=(1,1)/(64,8)/(64,64)，两文件系统×两策略×stay/move，共 72；F 只补 400 GiB×8、burst 三方法×两策略，共 18。不把全部 fork/规模/LLM 维度再翻倍，首次 pilot 不属于这组。

按 SCALE 的写入完成口径，F 的源树先远端就绪，创建返回与目标可用分别记时，全量 cp 核相同可用边界；该 8 子副本条件至少需 9.375 TiB 原始数据容量，额外计物理元数据与暂存，4 TiB 池不能执行。未上传源数据的 fork/恢复另做正确性资格，不混入只读基底性能。

M 先冻结同一逻辑写后工具 checkpoint，记录其 manifest SHA。writeback-handoff 的 archive-I/O 是受控回放负载，须先验证可信边界和可恢复回放状态，不能代替原生 OpenCode 会话/真实任务验证。只 drain 本次迁移集合，计入暂停；stay 对相同集合做同样步骤，邻居继续运行，不要求整个服务池上传队列归零。记录真实积压，不强制两策略在 checkpoint 有相同 dirty bytes。fsync/close 或单一 dirty=0 不能替代远端就绪；缺可靠观测/恢复接口则该消融未就绪。异步研发不自动更改主组配置。

同一协调端测暂停与首正确工具恢复，分解阶段；不能跨主机减 monotonic。VMID 不证明物理跨机，容器迁移必须换 executor host。真实模型恢复不叠加合成 LLM 等待。F/M 不同时争服务池，不新增多级共享目录实验。

一工作 Agent 一 VM/容器，独立 workspace/HOME/XDG、会话、挂载和缓存，实际 cgroup 包含 Agent 与 FUSE。scale 的所有客户端访问本组共享服务池；同一池一次一个 baseline，三完整区组随机臂顺序。额外并行 baseline 需要独立同规格服务池与换位，不能暗中共用。

缺少屏障、真实活跃度/结果聚合、原生 CLI 或语义资格时明确列在 readiness；不能按已有单机脚本顺序启动就算并发。单次 cohort 开始后不插入监督 AI 思考，监督步骤放计时之外。所有 Agent 结果齐全后再换臂/升档；失败、慢值和缺测全部保留，不自动重试/改预算。

按 provider 读取 [阿里云](../../../../infra/alicloud/PROVIDER.zh.md) 或 [自备](../../../../infra/servers/README.zh.md)。仅操作本组精确资源；来源/host-key 必须核验。provided 不默认允许重装、格式化或删除主机；共享机不全局清缓存。统一构建、内网分发，测量中不换二进制。

交付 readiness、冻结计划/placement、逐步命令/原始结果、每 Agent 与 cohort 计数/指标/失败表、SHA 保全及清理回执。先核下载与进程/FUSE/服务终止，再按归属清理；不触碰其他组、原输入或已保全资产。
