# C4：关闭周期采集的端到端试跑

已有两次可读回的 Off1，可以先报告端到端试跑，不用再开机。两次都关闭了三类节点的周期采集和外部接收器，保留任务计时、两次原生零债务检查、正常卸载和全量冷验。文件系统内置计数及 RustFS 发送逻辑保持原样。这是 10 万文件、单个子工作区的派生测试，不是跨机迁移，也不计入原 28 个正式单元。

| 秒 | BrewFS Flat（A 池） | JuiceFS（B 池） |
| --- | ---: | ---: |
| 创建开始到首次读到正确数据 | 8,424.806 | 3.230 |
| 创建后的文件同步 | 26.775 | 291.718 |
| 子工作区修改后同步 | 0.614 | 0.055 |
| 客户端任务总耗时 | 8,452.195 | 295.004 |
| 协调者放行到收到完成确认 | 8,453.367 | 295.385 |
| 重新挂载后全量校验父、子 | 4,916.559 | 1,181.656 |

原始命令确认 A 用 `cp -a --reflink=never` 做独立整树复制，B 用 `juicefs clone -p`。两次都验证首次 4 KiB 读，执行相同的预定子树修改，给 100,000 个文件做同步，冷挂载后检查完整父树和子树。父树清单 pin 均为 `02aeda272edbab9512595f7b968d840a9cfdc0e8302ed036399bf4151f08bd13`，预期子树清单 pin 均为 `c96cf044c5899f80e105d63b3bfdd8029985b7a615b0f679e3486bd001a512ce`；两个客户端档案的挂载都绑定同一计划文件 SHA，工作回执的 workload signature 相同。两次都有间隔超过一秒的零字节、零操作样本，且两次挂载各自退出码为 0、卸载完成。A 的排空计时为 1.662 秒；没有从 B Off1 找到同口径的排空计时，不拿两份采样之间的间隔代替。

本次逐包复核了[原 A 客户端档案](https://brewfs-agent-traces-20261023-4ccdae73.oss-cn-hangzhou.aliyuncs.com/pilot-results/20261111/c4-a-flat-off1-01/client.tar.gz)和[原 B 客户端档案](https://brewfs-agent-traces-20261023-4ccdae73.oss-cn-hangzhou.aliyuncs.com/pilot-results/20261111/c4-jfs-calibration-off1/client.tar.gz)的 SHA 与全部成员，各 57 个文件；从成员读取创建命令、工作计时、冷验 pin 与卸载回执。档案没有收录两个整树清单本体，因此这里核对的是保留回执中的清单 pin，不重新计算整树哈希。B 原批在归档时因槽位仍有进程而退出，随后单独归档了既有计时和校验；[恢复回执](evidence/preparation/c4-b-resume-01/off1-recovery.json)没有重跑负载。

可比较的是同一份逻辑工作在两个指定实现上的时间。两次同日分池运行、时间相隔约六小时，测试代码版本分别为 code-19 和 code-15。A 客户端为 BrewFS `ca07159`，B 为 JuiceFS `1.4.2+2026-10-22.46af7af`。[硬件回执](evidence/preparation/c4-b-live-01/cross-pool.json)确认两池当时规格、CPU 型号、内核及 Redis/RustFS 构建匹配，未证明同等 I/O 速度。两边计划的读缓存预算都是 512 MiB，但实现与预读、写缓存策略不同；没有周期计数可证明命中率或物理读写量相同。冷验都通过，A 还记录了父目录身份摘要。样本各一次，保留原时长，用于说明整树复制和原生 clone 在这个输入上的实际区别；不能用它判断 BrewFS 增量派生的收益或给出稳定的速度倍数。

如需测 BrewFS 增量派生的收益，另开端到端协议：同一池、同一冻结输入、预定冷热状态，先完成同引擎增量开启/关闭对照，再加 JuiceFS clone；按配对顺序重复。Flat 与 JuiceFS 可沿用现有 Off 执行步骤；增量两组需要单独的执行适配。用新请求固定代码、两次新挂载与全量冷验，沿用容量和物理锁检查；保留创建到首读、任务、排空、冷验和退出回执，独立归档，结果单列。原 On1 仍是开采集的旧校准轮；[旧验收](C4-OBSERVE.zh.md)和[新方案](../current/EXECUTION.zh.md)各自要求完整周期采集，端到端试跑不用于替代。
