# 最新BrewFS的native路线复查

使用未修改的BrewFS `ca07159`二进制。所有操作为本机功能检查，无云上测量或模型请求。

| 检查 | 实际结果 |
|---|---|
| workspace正常重挂后写入 | 原数据读回一致，修改并fsync仍返回EIO；修订后的脚本正常卸载，原Popen退出码0 |
| flat空库写入→重挂修改→再次重挂读回 | 全部通过，三个原挂载正常退出 |
| flat使用非空元数据DB | 在创建桶和挂载前拒绝 |

第一次flat检查误用了脚本默认的旧DB1：其中已有17个键和旧文件名，新桶中没有对应数据，读旧文件时报EIO。这是测试输入错误。原失败及正常关闭记录保留，不能作为新版本回归的证据。另选确认空的DB8后，原脚本通过；增加空库检查后，在空DB9再次通过。

`qualify-native-local.py`现用只读的SELECT/DBSIZE检查flat和云端资格库，不依赖本机安装redis-cli，不删除旧数据。同步检查失败后，保留失败结果并正常卸载原Popen，另存真实退出回执。`guard-checks.json`记录空库通过、非空库拒绝、workspace失败后正常收尾三项实际检查。

完整原始记录与Packed检查共用[功能检查原始包](../c3-packed-ca07159-100k/README.zh.md)。最初两次旧脚本的失败由操作者正常卸载，记录PID/start-tick和pidfd退出；没有补造当时已丢失的父进程退出码。
