## 归档后哪些副本可以回收

1. **归档是否完整。** `run-c4.py` 在采样器正常退出后复制原文，生成对象 TGZ，协调者收包后比对外层 SHA-256、逐成员大小和 SHA-256，拒绝缺失、重复、额外、延迟或特殊文件条目，再解包并审核 `raw/objects/o/<tag>` 全部采样和阶段标记。`calibrate-c4.py` 只在这些步骤通过之后写 `finished.json`。应同时核验本轮外层进程成功退出；孤立的 `finished.json` 不能代替进程和所有权检查。
2. **后续读取哪里。** `check-c4-calibration.py` 重验协调者 `archives/objects.tar.gz` 和 `raw/objects/o/<tag>`；工作节点的 `observers.json.directory` 字段仅取末尾 tag。`admit-c4.py` 使用协调者的校准、容量、首轮工作和冷验回执。后续五轮仍要读取工作节点 `/srv/ax-client/q/c4-a-flat-off1/verify/result.json`，并使用当前对象 collector 及 `/srv/ax-objects-0/q/<collector-name>`。这两项、其他 `q/`、原数据、所有协调者文件和对象 TGZ 都保留。当前六轮检查和正式准入不会读取以往对象节点的 `evidence/<tag>` 或 `o/<tag>`。
3. **逐轮可回收什么。** 在确认该轮完成、原采样进程已退出且没有后续轮正在使用该资源后，可单独校验 `evidence/<tag>` 与完整清单一致，再校验 `o/<tag>` 与清单中同前缀全部成员一致。若两树均被验证、独立持有协调者解包原文和完整 TGZ，可只回收这两个路径。不得删除 q、对象数据或压缩包。现有回收工具仅接受 `evidence/<tag>` 和既定校准暂存路径；它还需要原资源锁，不能趁暂停的父进程仍持锁时直接用来处理 `o/<tag>`。
4. **余量按峰值检查。** 只回收 `evidence/<tag>`，B 类比最终仍留 **3,109,722,710 B**；同时回收对应 `o/<tag>`，最终只留 **76,229,522 B** 的对象原始其他文件及压缩包。但下一轮仍必须容纳该轮双份原文和压缩包。B 类比逐轮回收后峰值约 **3,150,371,961 B**（含正式轮之前的残留），仍高于 A 原 844 MB 预测余量。不能用轮后可回收量代替轮内余量。需要在安全轮次边界独立测量同一块盘的可用空间，并在原七份副本和 20% 预留下另留单轮证据空间；无可核实余量则不放行下一轮。当前循环没有轮间余量门禁，单次 HTTP 响应大小上限也不是整轮存储上限。
