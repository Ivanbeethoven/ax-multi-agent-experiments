## 口径与验收边界

- 每臂 SHA、输入清单摘要、配置上限相同；独立从每份 raw `.stats` 重算六个 native 字段、逻辑字节、quiet 边界、两阶段和 E2E-minus-preparation，与 proxy 一致性逐项核验。八个元数据池的实际 capacity 与 peak/owned 边界及拒绝计数也逐份检查；缓存命中统计从原始卸载日志重解析。
- 首次 `.stats` bootstrap 会预热权限元数据；其流量与时间计入准备和 E2E。首次 traversal 不再是完全未经采样的冷态。约 0.5 秒 drain 是两臂都承担的静默观察窗；E2E 直接计时，不能重复叠加 bootstrap。
- retained remount 验证本地持久缓存复用：无新下载、runtime 无 GET/HEAD/body，但 mount manifest 仍需远端读取。private 两臂绕过 proxy/native，只能证明新私有卷、冷缓存重挂和父卷内容隔离，不能把其零 meter 当作零下载或正式 C4 资格。
- 响应体放大分母：首次为 `files*4096`，E2E 为 `2*files*4096`；GET 包含 Range，不能把两者相加。请求总数使用 GET+HEAD。
- 当前对象清单大小低于256MiB整对象缓存容量；没有验证超预算工作集或稀疏少量读取。网络是本机RustFS的S3兼容API，不是真实远端S3链路。
- 所有正式 arm 的 correctness、native warm gate、无错误和清理通过，八对 E2E 均改善。用户最新验收取舍以整体性能为准，因此本轮接受；首次 readdir 一致回退仍完整披露，原严格元数据非回退指标为 false。当前没有正式 C3/C4 distributed 结论。

完整逐臂数据、归档 hashes、timing 账目和限制见 `review.json`。四轮已齐。

`pack_cache.rs:209–224` 在下载 slot、1 MiB Stored 缓冲与 entry Control 准入（250–264）之前发 HEAD。后者不足会返回 None，转入 Range fallback；没有失败准入记忆来免除下一次同 key HEAD。HEAD 之前已有 transport 状态、driver 数、generation 和 Plans 准入，不能说它完全绕过准入。
