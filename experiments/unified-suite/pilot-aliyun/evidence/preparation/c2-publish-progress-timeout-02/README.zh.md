# C2：时间花在 Packed 发布阶段

2026-11-12，用 A 客户端盘上已有的 `pytest-full-02/initial`，614 文件、35,526,497 B。没有下载 trace、调用模型或启动回放。BrewFS `ca07159`、RustFS 指定分支 `f4ed2025` 在本轮前重新核过远端；生产器 SHA 和参数见 [intent](worker/intent.json)。

| 步骤 | 实测时间 | 结果 |
|---|---:|---|
| 两端 HTTP 存活、读就绪及对象端写就绪 | 0.397 秒 | 第一轮全部 HTTP 200 |
| 查询新桶 | 0.264 秒 | HTTP 404，名称未占用 |
| 创建新桶 | 6.430 秒 | HTTP 200 |
| 本地文件打包并发布到 RustFS | 300.001 秒 | 到原定上限后退出 -15，未完成 |

桶操作本轮使用 30 秒读超时，前轮为 3 秒。单独记录了两次调用，不重试创建。前轮没记具体调用，不能据此断言前轮也是创建桶超时。此轮已经证明服务就绪和桶操作可完成。

发布过程中对象数持续增加。结束后列出 145 个对象，共 24,520,277 B，没有最终 manifest；源数据没有改动。本次原始文件包括 300 个逐秒进程样本和周期对象计数。最后一个样本在约 299 秒，客户端进程累计 CPU 为 1.92 秒，线程主要等待 futex/epoll。它表明时间没有主要耗在客户端 CPU 运算上，尚不能把等待精确分到每个 PUT、读回校验、服务端磁盘或后台扫描。

对照性的[本地文件后端检查](../c2-local-publisher-01/README.zh.md)用同一生产器和源内容，在 5.53 秒生成并核验全部 182 个对象；这不是相同机器、相同存储后端的性能配对，不能相减当作网络耗时。两个结果均不算 C2 完整 trace 已通过。

原始小回执按字节保留，见 [SHA256SUMS](SHA256SUMS)。[独立云 API 复核](independent-stop-audit.json)确认 A 三台和原 jump 全部 `Stopped/StopCharging`；原 B 三台及九盘仍不存在。没有新增 ECS、云盘或公网 IP，新桶留存用于解释失败，不按桶名前缀批量清理。
