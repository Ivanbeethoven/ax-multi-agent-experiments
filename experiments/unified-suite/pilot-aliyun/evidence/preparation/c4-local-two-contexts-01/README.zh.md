# C4：同一 WSL 内重新挂载并读回原会话

这次只核对状态能否跟着共享卷打开。两次 JuiceFS FUSE 挂载使用同一份 Redis/RustFS 数据、不同的 Linux 挂载命名空间。源端写入冻结 checkpoint，导出原会话，排空并正常卸载；目标端用新缓存和空 HOME 挂载，先逐文件读回，再在仅有 loopback 的网络命名空间内执行 `opencode export`。目标未复制 workspace，没有调用模型。

目标首次导出前的全量树与源端关闭后的树相同，两端导出的原会话 SHA 相同。目标导出后树摘要发生变化，因此冷验放在第一次导出前；本次没有定位变化原因。两端记录零上传债务并正常退出；临时 Redis 和 RustFS 已停止并移除。

[回执](receipt.json)由当时工具保留的输出整理，临时原件已不在原路径。这是同一台机器的两个挂载上下文，使用独立本地脚本，未运行新 v2 执行器。该结果不计入正式跨机验收，也不用于性能对比。
