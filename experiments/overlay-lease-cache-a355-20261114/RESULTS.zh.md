# A355：Private Workspace 缓存优化结果

默认改为在有效独占租约下保留元数据缓存，容量仍为 **64 MiB**。写入、视图切换、租约失效和不确定提交沿用失效机制；写入的远端租约校验、版本冲突检查和最终提交没有移除。可用 `BREWFS_WORKSPACE_ROW_CACHE_POLICY=ttl` 恢复原来的到期策略。

代码：[f24b93e](https://github.com/brewfs/brewfs/commit/f24b93ebcb62630d9393c8410fbcd0f4c9289c75)，基线为 `0844a9d`。只在已有 A355 上运行独立 Redis/RustFS，未使用 SQLite、云机或新增付费资源。

三对重复交换执行顺序，使用相同优化 release、输入、缓存容量和 FUSE 参数。每个单元重新挂载、预热并核对内容；计时期间所有对照的对象读取请求和字节均为零。2/32 文件各测 257 轮；10,000 个实际文件各测 3 轮，包含 9,999 项子目录分页。不同输入的总时间不能直接横向比较。

下表为中位耗时，单位 ms。开销 = `100 × (Overlay / 对照 − 1)`；正数为更慢。完整逐次结果和阶段时间见[配对表](evidence/comparison.md)。

| 输入 | 旧 Overlay | 新 Overlay | 新版只读 lower | 新/旧 | 新/lower |
|---|---:|---:|---:|---:|---:|
| 2 文件 | 918.461 | 931.744 | 656.569 | +1.45% | +41.91% |
| 32 文件 | 8639.808 | 8730.757 | 7210.845 | +1.05% | +21.08% |
| 10,000 文件 | 40654.728 | 29930.874 | 26933.443 | **−26.38%** | **+11.13%** |

一万文件的三对新/旧变化为 −26.02%、−25.37%、−27.48%。2 文件为 −1.68%、+4.81%、+1.45%；32 文件为 +2.26%、−5.14%、+1.05%。小输入没有证明稳定加速。只读 lower 是新版同引擎路径，不与“修改前 Overlay”混为一个对照。

一万文件中，两版实际行缓存占用均为 31,027,437 B，低于 67,108,864 B 上限。各次计数一致：

| 计时段计数 | 旧 Overlay | 新 Overlay |
|---|---:|---:|
| 行缓存缺失 | 39,744 | 0 |
| 上层区间查询 | 10,000 | 0 |
| 实际 Redis MGET | 29,750 | 6 |
| 实际 Redis ZRANGEBYLEX | 20,020 | 20 |
| Redis 执行命令合计（不含 INFO） | 50,641 | 737 |

Redis 合计包含事务和 Lua 内部命令，也包含计时段内的后台活动，不等于网络往返数。新版仍有目录租约校验和后台元数据操作；对象读取为零不表示没有 Redis 请求。每个单元另保存计时段之外的 MONITOR 审计。

一万文件阶段时间如下，采用三次的**算术均值**，不与上表中位总时间相加：

|---|---:|---:|---:|
| 文件 open | 23772.331 | 17173.393 | 6598.938 |
| pread | 10486.328 | 6709.020 | 3777.309 |
| 文件 fstat | 2695.584 | 2533.337 | 162.247 |
| 文件 close | 2906.262 | 2790.439 | 115.823 |
| opendir | 3.700 | 3.589 | 0.111 |
| 列目录 | 86.206 | 82.763 | 3.442 |

目录 rewind 会先重新检查远端租约及完整层版本；无变化才复用原目录视图。小输入的上层空目录缓存检查从 514 次降为 257 次，但 **OPENDIR 与首次 READDIR 的远端检查仍各一次**，MGET 仍为 514 次。提前撤销没有即时通知，不能将两次独立请求共用未经重新确认的证明。本轮没有证明目录延迟的稳定改善。

为单独验证 TTL，使用**同一个新版二进制**，只切换 `ttl`/`lease` 策略。32 文件预热后分别空闲至少 61 秒，记录随后第一轮：

| 配对 | TTL ms | Lease ms |
|---|---:|---:|
| 1 | 81.263 | 37.761 |
| 2 | 84.213 | 36.826 |
| 3 | 78.494 | 37.451 |
| 中位数 | 81.263 | 37.451 |

第一轮中位耗时减少 **53.91%**。每次 TTL 策略均产生 132 次行缓存缺失、32 次区间查询、101 次 MGET 和 66 次范围查询；lease 策略分别为 0、0、2、0。服务器内部的权限缺失处理均值 7.915 ms、区间查询 11.587 ms 均降至零；目录租约校验仍执行 2 次。该组开启阶段计时，只用于解释原因；表中是调用者第一轮操作耗时，排除了等待和外部 HTTP 采样，不把含采样的整批耗时当正常性能结果。

正确性与混合 I/O：

- 477 项 KV、24 项行缓存、33 项 open/read preparation、19 项本地元数据、租约和目录回归通过。新目录测试覆盖跨 256 项分页、上层新增、删除标记、属性变化及提前撤销；缓存测试覆盖容量、失效、取消提交和旧缓存引用不能恢复权限。
- 真实 FUSE 完成 600 次原子替换及 9,600 次读取；混合用例完成 26,110 次写入、61,107 次读取；12 个正确性单元最终 fsync 和重新挂载读回通过，没有向调用者返回 ENOENT/EIO。
- `fmt`、workspace check/build、两种 FUSE runtime check、Clippy 和相关 shell 检查通过。按用户要求没有执行包含 SQLite 的完整 workspace 单元套件，不能称为完整 CI 全通过。
- fio 使用 16 MiB 已写入并完整读回的文件、4 KiB direct、70% 读、30 秒，分别三对。读写吞吐变化均小于 1%，P99 最大增加 2.80%；最终 fsync 和卸载均完成。各次数据见[检查汇总](evidence/check-summary.json)。

| fio 所在输入组 | 读 kB/s，旧→新 | 写 kB/s，旧→新 | 读 P99 ms，旧→新 | 写 P99 ms，旧→新 | 含最终 fsync 秒，旧→新 |
|---|---:|---:|---:|---:|---:|
| 2 文件 | 273.716→272.851 | 113.013→112.018 | 76.022→74.973 | 3.719→3.752 | 31.044→30.838 |
| 32 文件 | 272.636→272.986 | 112.143→112.877 | 74.973→77.070 | 3.752→3.785 | 30.875→31.001 |

剩余时间主要在 open 和 FUSE 调用路径。61 秒诊断的 lease 组中，32 次客户端 open 合计约 20 ms，而 FUSE OPEN 回调本身约 0.79 ms；差额还包含路径查找、属性请求、内核和用户态等待，尚未进一步逐项归因。没有验证跨机高 RTT、更大缓存工作集或长时间生产负载；这里的 11.13% 只对应本次一万文件热读。

[原始归档](evidence/results.tar.gz)保存 1,358 个文件，包括逐次数据、实际命令、源码清单、补丁、二进制 SHA 和全部检查日志；[文件清单](evidence/inputs.json)、[归档校验](evidence/archive.json)均已在本地逐项验证。`accepted/` 为本轮完成结果；`prior-1/` 保留最初的测试编译失败，`prior-2/` 保留被替换的中间构建。后者没有运行性能测试，终止等待器时留下的 `measure.exit=0` 已由原目录的 `superseded.json` 解释，不能当成功测量。

源码和二进制绑定见[发布记录](evidence/publication.json)：编译时的 2,023 个源码文件与最终提交内容一致，测量使用的补丁 SHA 也与提交后的差异完全一致。当前 `build_check.sh` 已改为格式检查后直接校验源码清单并复制补丁，避免复现时漏放补丁；本次实际执行脚本仍保存在归档中。所有测试容器与 BrewFS 进程已退出，测试挂载和临时代理隧道已清理；原有 `/tmp/fuse` 挂载保留。
