# 1. 基础 fio

状态：已确认。统一参数与 Dynamic 比较方法见 [完整方案](../docs/PLAN-REVIEW.md)。

线程选择、采集开销检查和复测结果管理见 [fio 运行配置与复测](fio-runtime.md)。

三个系统分别生成内容相同的 8 个 256 MiB 文件，共 2 GiB。原版 BrewFS 使用 `volume_format=flat`；Workspace Native 在 fork 出来的空工作区当前层写入数据；JuiceFS 使用独立测试目录。输入准备在计时前完成。

每个挂载使用 16 GiB 内存、56 GiB 读 SSD 缓存和 8 GiB 写暂存预算，两种文件系统及所有块配置保持一致。首次读取使用新缓存目录，第二遍复用同一挂载，分别保存 S3 流量与内存回收统计。

固定 8 个 fio job，使用 `direct=1`：

| 负载 | 应用请求 | 所有 job 合计工作量 |
|---|---:|---:|
| 顺序读、顺序写 | 1 MiB | 各 2 GiB |
| 随机读、随机写 | 4 KiB | 各 64 MiB |

- 主比较：BrewFS 原版独立卷（`flat`）、BrewFS Workspace Native、JuiceFS Redis，各运行顺序读、顺序写、随机读、随机写。
- Dynamic 比较：关闭时 BrewFS hint 为 `off`，访问原版 RustFS 1.0.5（19000 端口）；开启时 hint 为 `auto`，访问修改版 9000 端口。
- 块尺寸比较：只在随机读、随机写中增加固定 B=64 KiB、4 MiB，其他参数保持不变。
- 读取从客户端冷缓存开始；写入每累计 64 MiB 执行 fsync，最后等待上传完成。
- 指标：吞吐、IOPS、P99、应用/S3/磁盘读写字节。记录实际 B/q。

共 20 组系统配置，各运行一次，合计 **20 次运行**。复用 fio 配置生成、`c1-io-helper`、挂载和指标采集代码。

## 卷模式与比较方法

- `brewfs-flat` 为原版独立卷，不设置 Workspace ID，不执行 fork 或父层解析。与 Workspace Native 使用同一 BrewFS 二进制、8 个 Tokio worker、相同缓存预算和 Redis 服务。
- 原版独立卷四项编号为 `01-io-17-r1` 至 `01-io-20-r1`，依次为顺序读、顺序写、随机读、随机写；分别使用 Redis DB 11–14 和独立对象桶。
- 原版与 Workspace 主比较均开启 Dynamic，访问修改版 RustFS 9000。Dynamic 关闭和固定块尺寸测试继续在 Workspace Native 中执行。
- 原版与 Workspace 当前层的差值用于分析 Workspace 读取与写入开销；父层查询和首次覆盖写的开销由第 2 组的父工作区／子工作区比较回答。
- 保存明确的 `system`、`volume_format`、二进制版本、线程数、缓存和后端端点。读取分别记录冷／热吞吐、P99、S3 请求与字节、CPU 时间；写入记录应用完成、上传完成和跨机器重新挂载检查。

## 执行与输出

在仓库根目录执行整组小数据检查：

```powershell
ssh.exe idcai-60001 /srv/ax-idcai-20261113/venv/bin/python3 /srv/ax-cluster/direct/scripts/run_suite.py --check --group 01-io
```

检查使用 8 个 4 MiB 文件，每项执行 16 MiB I/O，覆盖上述 20 个条件。正式实验使用同一脚本和配置，每个文件为 256 MiB：

```powershell
python infra/idcai/start_suite.py --group 01-io
```

配置位于 `configs/experiment-suite.json`；fio 参数生成、数据准备和读回检查位于 `bench/cluster/runtime/run_c1.py`，统一调度位于 `bench/cluster/runtime/run_suite.py`。准备环境与下载结果的命令见 [运行说明](../docs/RUNNING.md)。

小数据结果位于 `/srv/ax-cluster/runs/direct/run-002/checks/01-io/`；正式结果位于 `/srv/ax-cluster/runs/direct/run-002/01-io/`。各次执行保存 fio 配置、原始 JSON、挂载参数、阶段指标、读回检查和 `result.json`。

测量与内容检查完成后保存 `measurement.json` 和 `result.json`，随即进入下一项。各子工作区与对象数据保留至整轮结果归档。
